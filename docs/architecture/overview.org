#+TITLE: Overview
#+OPTIONS: ^:{}

One SvelteKit frontend runs in four places. What changes between them is where the manga files are and who parses the archives.

| Mode               | Files are                        | Archives parsed by                 | Provider                   |
|--------------------+----------------------------------+------------------------------------+----------------------------|
| Browser            | Picked or dropped =File= objects | =klwasm= in a Web Worker           | =UploadProvider=           |
| Self-hosted server | On the server's disk             | =klserver=, over HTTP              | =ServerLibraryProvider=    |
| Desktop / Android  | On the device's disk             | Tauri commands (=src-tauri=)       | =NativeFilesystemProvider= |
| LAN share          | On the desktop's disk            | =klserver=, run by the desktop app | =ServerLibraryProvider=    |

* Stack

| Layer     | Technology                                     |
|-----------+------------------------------------------------|
| Framework | Svelte 5 (runes), SvelteKit 2                  |
| Language  | TypeScript (strict)                            |
| Styling   | Tailwind CSS 4, Source Code Pro monospace font |
| Desktop   | Tauri 2 (Rust)                                 |

* Rust crates

#+begin_example
crates/
├── klparse/   ZIP and ZIP64 parsing, chapter numbers and sorting, ComicInfo, collation
├── klfs/      klparse over files on disk, with a cache of parsed central directories
├── klwasm/    wasm-bindgen bindings to klparse, for the browser
└── klserver/  axum server, with a SQLite index of the library
src-tauri/     desktop and Android app; uses klparse and klfs
#+end_example

All four modes sort chapters and read metadata with the same =klparse= code, so a library looks the same everywhere.

* Source providers

The reader doesn't know which mode it's in. It's given a =SourceProvider= (=src/lib/sources/types.ts=), which lists chapters, reads metadata and turns a page into a URL. There are two kinds:

- Bulk (=getPageUrls=) :: returns every page URL of a chapter at once. Used when pages are plain HTTP URLs, as with a server.
- Lazy (=getPageUrl=) :: returns one page at a time. Used when getting a page means extracting it into a blob URL, as with uploaded files and native archives.

See [[file:page-loading.org][Page loading]] for how each is read.

* Which server

=apiUrl()= (=src/lib/utils/constants.ts=) prefixes API paths with the server URL stored in =localStorage= under =kl:serverUrl=, and appends the server's access key, stored under =kl:serverKey= (see [[file:../api/http.org][HTTP server]]). Empty URL means same-origin, which is the case when =klserver= serves the frontend itself; that page takes the key from a =?key== in its own address. The packaged apps set both when connecting to a server, including through a =konigslibrary://connect= link (=src/lib/sources/server-connect.ts=), which is what the LAN share QR code holds.

=src/lib/sources/connection.svelte.ts= polls =/api/ping= every 3 seconds while anything is watching, to show the server going offline or coming back.

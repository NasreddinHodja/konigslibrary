One SvelteKit frontend runs in four places. What changes between them is where the manga files are and who parses the archives.

| Mode               | Files are                        | Archives parsed by                 | Provider                   |
|--------------------+----------------------------------+------------------------------------+----------------------------|
| Browser            | Picked or dropped =File= objects | =klwasm= in a Web Worker           | =UploadProvider=           |
| Self-hosted server | On the server's disk             | =klserver=, over HTTP              | =ServerLibraryProvider=    |
| Desktop / Android  | On the device's disk             | Tauri commands (=src-tauri=)       | =NativeFilesystemProvider= |
| LAN share          | On the desktop's disk            | =klserver=, run by the desktop app | =ServerLibraryProvider=    |

All four modes sort chapters and read metadata with the same =klparse= code, so a library looks the same everywhere.

* Source providers

The reader doesn't know which mode it's in. It's given a =SourceProvider= (=src/lib/sources/types.ts=), which lists chapters, reads metadata and turns a page into a URL. There are two kinds:

- Bulk (=getPageUrls=) :: returns every page URL of a chapter at once. Used when pages are plain HTTP URLs, as with the server's own page.
- Lazy (=getPageUrl=) :: returns one page at a time. Used when getting a page means extracting or fetching it into a blob URL, as with uploaded files, native archives, and a server that needs the bearer header.

See [[file:page-loading.org][Page loading]] for how each is read.

* Which server

=apiUrl()= (=src/lib/utils/constants.ts=) prefixes API paths with the server URL stored in =localStorage= under =kl:serverUrl=. Empty URL means same-origin, which is the case when =klserver= serves the frontend itself. The packaged apps set it when connecting to a server, including through a =konigslibrary://connect= link (=src/lib/sources/server-connect.ts=), which is what the LAN share QR code holds; a new server drops the old one's session.

Requests go through =apiFetch()= (=src/lib/api/auth.svelte.ts=), which carries the session:

- Same origin :: the =kl_session= cookie. Covers and pages stay plain URLs, since =<img>= sends the cookie; =ServerUrlProvider= is bulk.
- Another server :: =Authorization: Bearer=, with the token kept under =kl:serverToken=. =<img>= can't send the header, so covers are fetched into blob URLs (=authedSrc()=, =src/lib/api/authed-src.svelte.ts=) and =ServerBlobProvider= is lazy. Downloads pass the token to =download_file=.

=openServerManga()= (=src/lib/sources/library.ts=) picks the provider. A =401= anywhere sends the app to =/login=, which sets up a server with no admin yet (the setup token is in its log) or logs in. Logins from the apps also keep the server's device token under =kl:deviceTokens=, per server, so a lockout from someone guessing the password doesn't lock them out.

=src/lib/sources/connection.svelte.ts= polls =/api/ping= every 3 seconds while anything is watching, to show the server going offline or coming back.

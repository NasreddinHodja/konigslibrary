#+TITLE: konigslibrary
#+DESCRIPTION: Client-side manga reader

Manga reader that opens ZIP and CBZ archives. Runs in the browser, as a desktop/mobile app (Tauri), or as a self-hosted server for LAN access. No accounts required.

#+html: <p align="center"><img src="static/help/home-mobile.jpeg" alt="Mobile home" width="260">&nbsp;&nbsp;<img src="static/help/manga-mobile.jpeg" alt="Mobile manga detail" width="260">&nbsp;&nbsp;<img src="static/help/reader-mobile.jpeg" alt="Mobile reader" width="260"></p>

* Features

- *In the browser*: open a manga folder, or drop a chapter =.cbz= to read it
  right away. Nothing to install.
- *Desktop app* (Windows, Linux): point it at your library folder, or add
  manga folders to the app's own library.
- *Android app*: add chapter =.cbz= files to the app's library, or download
  manga from your computer to read offline.
- *Huge libraries*: the server indexes its manga directory in a database and
  serves the list a page at a time, searchable by title.
- *Computer to phone*: in the desktop app, Settings → Share to LAN, then scan
  the QR code with your phone.
- *Server*: run it on a NAS or home server and read from any device on your
  network.

* Architecture

#+begin_src
src/lib/
├── api/             # Manga metadata fetching (server, device)
├── browsers/        # Library UI: Device/Server tabs, cards, upload button
├── chapter-loader/  # Chapter loading hook + preloader
├── chapters/        # Chapter tiles, thumbnails, EndOfChapter UI
├── commands/        # Command registry and keybinding actions
├── context/         # ReaderServices factory (createReaderServices)
├── events/          # Typed event bus
├── keyboard/        # Configurable keybindings + help overlay
├── plugins/         # Plugin system (runner, registry, window title)
├── sources/         # Data sources (upload, server, device, downloads, imports)
├── theme/           # Theme presets and colours
├── ui/              # Shared UI components (list panel, toast, buttons)
├── utils/           # Constants, types, platform detection
├── viewers/         # Reading modes (scroll, page-turn) + viewer registry
└── zip/             # Byte-range plumbing around the wasm parser
#+end_src

The archive parser is a Rust workspace, built once and used everywhere:

#+begin_src
crates/
├── klparse/         # ZIP64 parsing, chapter grouping, JS-compatible collation
├── klwasm/          # wasm-bindgen bindings — the browser's no-backend path
└── klserver/        # axum binary — LAN sharing and self-hosted deployments,
                     #   with a SQLite index of the library
#+end_src

The browser and the server run the same parsing code, so a fix in one is a fix
in both. The wasm build keeps the lazy read behaviour that makes the plain
website work with no backend at all: opening a 2GB CBZ reads only the archive's
tail, its central directory, and the page on screen.

* Usage

** Browser

Visit the deployed site and open a manga folder (see [[Library Structure]]), or drop a
single chapter =.cbz= to read it right away.

** Self-hosted server

The easiest way to share your library with a phone on the same network: open the
[[Desktop App (Tauri)][desktop app]], go to Settings -> Share to LAN, and scan the QR code with your
phone's camera app (the mobile app must already be installed). No separate
install or script needed.

For a headless/always-on setup (NAS, homelab box, no GUI), build and run the
server yourself:

#+begin_src sh
bun install
bun run serve
#+end_src

=bun run serve= builds the frontend, builds the =konigslibrary-server= binary,
and runs it. Once built, the binary is standalone — no Bun, Node or Rust needed
to run it, just the =build-local/= directory beside it (its own output,
separate from the Tauri/website builds' =build/=, so a later =bun tauri
build= or =bun run build:android= can't silently swap out what this serves):

#+begin_src sh
KL_STATIC_DIR=./build-local MANGA_DIR=~/Manga NO_BROWSER=1 \
  crates/target/release/konigslibrary-server
#+end_src

See =konigslibrary.service= for a systemd user unit that does exactly this.

Set =MANGA_DIR= to your manga directory:

#+begin_src sh
MANGA_DIR=~/Manga bun run serve
#+end_src

Or configure it through Settings in the UI (saved to =konigslibrary.json=).

** Desktop App (Tauri)

The [[https://github.com/NasreddinHodja/konigslibrary/releases/latest][latest GitHub release]] has a Windows installer (=-setup.exe=) and a Linux
AppImage.

To build it yourself:

#+begin_src sh
bun run tauri:local          # dev mode
bun tauri build              # release build
bun run build:desktop        # Linux AppImage, built in Docker, lands in dist/
#+end_src

** Android

A signed APK is available on the [[https://github.com/NasreddinHodja/konigslibrary/releases/latest][latest GitHub release]].

* Library Structure

A manga is a folder holding one =.cbz= (or =.zip=) per chapter and, optionally,
a cover image named =cover.*=.

#+begin_src
MANGA_DIR/
├── One Piece/
│   ├── cover.jpg
│   ├── chapter_0001-00.cbz
│   ├── chapter_0002-00.cbz
│   └── chapter_0002-05.cbz
└── Berserk/
    ├── cover.png
    ├── 001.cbz
    └── 002.cbz
#+end_src

- Each subdirectory of =MANGA_DIR= is one manga
- Each =.cbz=/=.zip= directly inside it is one chapter; every image in the
  archive is a page, whatever folders it is nested under
- Loose images, subfolders and other files in a manga folder are ignored
- Hidden files/folders (starting with =.=) are ignored

In the browser, open a manga folder with the same layout, or a single chapter
archive.

** Metadata

Title, summary, authors, tags and status come from =ComicInfo.xml= inside the
chapter archives. Only the first and last chapters are read: the first one's
values win, and the last one fills whatever the first lacks. Without it, the
folder name is the title.

| Element               | Shown as                       |
|-----------------------+--------------------------------|
| =Series=              | Title                          |
| =Summary=             | Description                    |
| =Year=                | Year                           |
| =Writer=, =Penciller= | Authors (comma-separated)      |
| =Genre=, =Tags=       | Tags (comma-separated)         |
| =Status=              | Status badge, shown as written |

=Status= is not in the ComicInfo v2.1 schema; it is an extension. An archive
with =Count= but no =Status= is shown as complete.

** Sorting

Chapters sort lexicographically. Zero-pad file names to get correct numeric order:

| Wrong                | Right                  |
|----------------------+------------------------|
| =ch1=, =ch10=, =ch2= | =ch01=, =ch02=, =ch10= |

Archives named =chapter_<major>-<minor>= are shown
as chapter numbers: =chapter_0044-00= is "Ch. 44" and =chapter_0044-05= is
"Ch. 44.5". Any other name is shown as is.

** Supported image formats

JPEG, PNG, GIF, WebP, AVIF, BMP.

*** Android

Building/running the Android app additionally needs the Android SDK and NDK.
Gradle needs a JDK 17 to run its daemon (CI pins this version — see
[[file:.github/workflows/release-android.yml][release-android.yml]]); the project's Gradle wrapper is configured with a
[[file:src-tauri/gen/android/gradle/gradle-daemon-jvm.properties][daemon JVM criteria]] (=gradle/gradle-daemon-jvm.properties=) requesting JDK 17,
so Gradle auto-detects (or auto-downloads, via the Foojay toolchain resolver)
a matching JDK on its own — no need to set =JAVA_HOME= or change your system's
default JDK, even if it's a much newer version.

=bun run build:android= is unsigned unless a release keystore is configured —
copy [[file:src-tauri/gen/android/app/key.properties.example][key.properties.example]] to =key.properties= (gitignored) next to it and fill
in your keystore's path/passwords. CI supplies the same four values as
=KEYSTORE_PATH=/=STORE_PASSWORD=/=KEY_ALIAS=/=KEY_PASSWORD= env vars instead
(see [[file:.github/workflows/release-android.yml][release-android.yml]]). Either way, signing happens inside the normal
Gradle build (=build.gradle.kts='s =signingConfigs=) — there's no separate
=apksigner= step to run or SDK build-tools version to match.

* Keyboard Shortcuts

All shortcuts are rebindable from Settings. Defaults:

| Key        | Action                          |
|------------+---------------------------------|
| =j= / =↓=  | Next page                       |
| =k= / =↑=  | Previous page                   |
| =l= / =→=  | Next page (prev in RTL)         |
| =h= / =←=  | Previous page (next in RTL)     |
| =n= / =]=  | Next chapter                    |
| =p= / =[=  | Previous chapter                |
| =z= (hold) | Zoom to cursor (page-turn mode) |
| =s=        | Toggle sidebar                  |
| =b=        | Back to library                 |
| =m=        | Toggle scroll / page-turn mode  |
| =r=        | Toggle LTR / RTL                |
| =-= / ===  | Zoom out / in (scroll mode)     |
| =?=        | Show keyboard shortcuts help    |
| =Escape=   | Close sidebar or help dialog    |

Click left/right halves of the page-turn viewer to navigate.
